# M5 持ち越し課題の検証（項目2〜5）

M4.5 が M5 に持ち越した6項目のうち、人間評価者・実デプロイ環境が必要な
項目1（講師評価との順位相関）・項目6（本番RTF再測定）は保留とし、
自動化できる項目2〜5を先に検証した。

| # | 課題 | 結論 |
|---|---|---|
| 4 | 反復練習（同じ2小節を10回）への追従 | **問題なし**。F1 0.925、他条件と同水準。跳躍ペナルティの積み上がりは見られない |
| 3 | 実録音での弾き直しアライメント精度 | **良好**。正解率 93.9〜97.1%、弾いていない箇所への誤対応は0% |
| 5 | ピアノ以外の音（メトロノーム・話し声）の混入 | **要対策**。note F1 が最大10.4pt低下する、無視できない劣化 |
| 2 | 実 MusicXML を参照譜にした場合の挙動 | **形式的には対応可能**。ただしタイ結合など MIDI 量子化にはない前処理が要る |

検証環境・データセットは M4/M4.5 と同じ（[m4-report.md](m4-report.md) 8章）。
追加で `music21` を PoC 環境に導入した（`pip install music21`、依存追加なし・軽量）。

## 1. 反復練習（同じ2小節を10回）への追従

### 1.1 何を確かめたかったか

M4.5 で導入した跳躍付き DTW（`JUMP_PENALTY = 10.0`）は、弾き直し・部分練習では
機能することを確認したが、**同じ箇所を何度も繰り返す「集中練習」**は未検証だった。
跳躍のたびにペナルティが乗るため、テイク数が多いと累積してアライメントが
壊れるのではないか、という懸念があった。

### 1.2 方法

`perturb_replay.py` に `repeat10` 条件を追加した。曲の45%地点から2小節を
10回繰り返した後、残りを最後まで弾く構成（計12セグメント＝11回の跳躍）。
他の弾き直し条件（`r_retry3` 等）と同じく、MIDI レベルで時間軸を組み替えるだけの
検証であり、採譜ノイズは含まない。

### 1.3 結果

| 条件 | F1 | falseMiss | 前テイク誤対応 | 別音符誤対応 |
|---|---|---|---|---|
| `r_none`（対照） | 0.9360 | 0.0000 | 0.0000 | 0.0640 |
| `r_stop` | 0.9352 | 0.0000 | 0.0000 | 0.0648 |
| `r_repeat10`（10回・11跳躍） | **0.9254** | 0.0000 | 0.0008 | 0.0716 |
| `r_retry3`（3回・4跳躍） | 0.9243 | 0.0001 | 0.0046 | 0.0685 |
| `r_retry_long`（1回・大跳躍） | 0.9210 | 0.0002 | 0.0005 | 0.0750 |

`r_repeat10` の F1 は `r_retry3`（跳躍4回）や `r_retry_long`（跳躍1回）と
ほぼ同水準で、跳躍回数が11回に増えても劣化が積み上がっていない。
前テイクへの誤対応率も 0.08% と極めて低い。

**結論: JUMP_PENALTY=10.0 のままで反復練習に対応できる。設計変更は不要。**
跳躍は「列ごとの最小値を持ち回る」実装（`dtw_path_jump`）で、ペナルティが
毎回の遷移で加算されるのではなく毎回同じ固定値として比較されるため、
跳躍回数に応じて不利になる構造にそもそもなっていない。

## 2. 実録音での弾き直しアライメント精度

### 2.1 何を確かめたかったか

M4.5 の弾き直し検証は ground truth MIDI の時間軸組み替えのみで、
**採譜モデル自体のノイズ**（ピッチ誤検出・onset ずれ・見落とし等）とは
独立に測定していた。実際のアプリでは実録音を採譜してからアライメントするため、
「採譜ノイズ」と「弾き直しへの追従」が組み合わさったときに問題が起きないかを
確かめる必要があった。

### 2.2 方法（新規スクリプト `perturb_replay_audio.py` / `evaluate_replay_audio.py`）

`perturb_replay.py` と同じセグメント計画（`make_plan()`）を使い、
今度は **MIDI ではなく実録音（`piece0X.clean.wav`）を波形レベルで切り出して結合**した。
間（pause）は無音を挿入する。これを ONNX 採譜モデルに通し、`align.py --mode jump`
で参照譜（スコア）に対応付け、評価した。

実音声版は採譜結果の音符インデックスが ground truth と1対1に対応しないため、
`evaluate_replay.py` のような outIndex 完全一致は使えない。代わりに
「参照音符が最後に弾かれた時刻」を真値とし、対応付いた採譜音符の実際の発音時刻が
それに近いか（許容 ±0.3秒。テイク間隔 1.2秒以上より十分小さい）で判定する。

検証コスト抑制のため、対照・中程度の弾き直し・最悪ケース・反復練習の
4条件 × 2曲（piece00, piece01）に絞った（計8ファイル、ONNX RTF 平均0.68）。

### 2.3 結果

| 条件 | 正解率 | 前テイク誤対応 | 別音符誤対応 | 検出漏れ | 弾いてない箇所への誤対応 |
|---|---|---|---|---|---|
| `a_partial_retry` | **0.9710** | 0.0026 | 0.0026 | 0.0239 | 0.0000 |
| `a_none`（対照） | 0.9567 | 0.0000 | 0.0086 | 0.0348 | 0.0000 |
| `a_repeat10` | 0.9505 | 0.0008 | 0.0163 | 0.0325 | 0.0000 |
| `a_retry3` | 0.9388 | 0.0109 | 0.0155 | 0.0348 | 0.0000 |

**結論: 実録音でも弾き直し・反復練習への追従は良好。**
正解率は93.9〜97.1%で、対照条件（採譜ノイズのみ、弾き直しなし）の95.7%と
同水準か、それ以上。弾いていない箇所への誤対応（spurious）はどの条件でも0%。
M4.5 が MIDI レベルで確認した結論（跳躍付き DTW が弾き直しに対応できる）は、
実際の採譜ノイズが乗っても崩れない。

### 2.4 この検証の限界

- 2曲・4条件に絞っており、全4曲・全8条件の網羅ではない。
- 切り出し元は `clean` 条件のみ。`room`/`phone` など劣化録音との複合効果は未検証。
- 実際の初中級者の弾き直しはこれより不規則（テンポが揺れる、同じ小節でも
  弾き方が変わる）。ここでの検証は「時間軸の組み替え方」自体の妥当性の確認に留まる。

## 3. ピアノ以外の音（メトロノーム・話し声）の混入

### 3.1 何を確かめたかったか

本アプリの利用者は自宅で練習しながらスマホ等で録音する。
メトロノームのクリック音や家族の声が録音に混ざるのは日常的に起きる。
これが採譜（ひいては音程・リズム・ペダル指標）をどれだけ壊すかは未検証だった。

### 3.2 方法（新規スクリプト `add_nonpiano_noise.py`）

Azure Speech 等の実音声合成は使わず、
「ピアノと無関係な音がどれだけ混ざると採譜が壊れるか」を切り分けるため、
帯域・時間特性だけを模した合成音を使った。

- `metronome`: 92 BPM の減衰トーンバースト（2.2kHz、20ms）
- `voice`: 300–3400Hz に帯域制限した断続的なバースト雑音（発話の on/off パターンを模す）
- `metronome_voice`: 両方を重畳

`piece00.clean.wav` / `piece01.clean.wav` にそれぞれ混ぜ、ONNX 採譜モデルに通し、
`evaluate_transcription.py`（M4 で使ったものと同じ、ground truth MIDI との直接比較）
で note F1 / pedal F1 への影響を測った。

### 3.3 結果

| 条件 | note F1 | note off F1 | velocity 相関 | pedal F1 |
|---|---|---|---|---|
| `clean`（対照） | 0.9744 | 0.2164 | 0.9506 | 0.8591 |
| `metronome` | 0.9042（**−7.0pt**） | 0.1920 | 0.9423 | 0.8318（−2.7pt） |
| `voice` | 0.9280（**−4.6pt**） | 0.1560 | 0.8990 | 0.8236（−3.6pt） |
| `metronome_voice` | 0.8704（**−10.4pt**） | 0.1472 | 0.8864 | 0.7997（−5.9pt） |

**結論: 非ピアノ音の混入は無視できない劣化を引き起こす。設計上の対策が必要。**

- メトロノームのクリック音単体で note F1 が7ポイント低下する。
  クリックの立ち上がりが偽陽性の onset として検出されている可能性が高い。
- 話し声様のバースト雑音も4.6ポイント低下させる。帯域が声域と重なるため、
  ピアノの倍音成分の検出を邪魔していると考えられる。
- 両方が重なると劣化がほぼ加算的（−10.4pt）で、相殺は起きない。
- pedal F1 への影響も無視できない（最大−5.9pt）。

### 3.4 設計への示唆

- **録音ガイダンス**: アプリの録音画面で「内蔵/外部メトロノームの音量を下げる」
  「別室で録音する」等のガイドを表示すべき。
- **視覚メトロノーム推奨**: アプリ内メトロノームを提供する場合、音ではなく
  画面フラッシュ等の視覚提示をデフォルトにすることで、この劣化要因自体を
  利用者体験の設計で回避できる。
- **前処理での抑制**: クリック音除去（ノッチフィルタ等）は、メトロノームの
  周波数が機種依存で不定なため汎用的な対策が難しい。優先度は低い。

## 4. 実 MusicXML を参照譜にした場合の挙動

### 4.1 制約 — このデータセットでは音声との突き合わせができない

本 PoC のデータセット（MAESTRO の90秒抜粋 4曲）には、対応する公式 MusicXML が
存在しない。MAESTRO は演奏 MIDI ベースのデータセットで、しかも各曲は
演奏全体からランダムに切り出した90秒間であるため、市販・公開楽譜の
どの版のどの小節に対応するかを特定できない。したがって「実 MusicXML ＋
対応する実演奏」の組み合わせでの検証は、このデータセットでは行えない。

### 4.2 方法（新規スクリプト `musicxml_reference.py`）

音声との突き合わせの代わりに、次の2点に絞って検証した。

1. `reference.json` のスキーマ（`index` / `pitch` / `startBeat` / `measure` /
   `beatInMeasure` / `durationBeats`）が、実際の MusicXML からも構築できるか。
2. MIDI 量子化にはない、MusicXML 特有の前処理課題の洗い出し。

`music21`（軽量・追加インストール可能）を使い、corpus 内の公開楽譜
（Bach コラール、Chopin マズルカ）を読み込んで `reference.json` 形式に変換し、
これに軽いタイミング揺らぎを加えた「演奏もどき」を `align.py --mode jump`
にそのまま通した（実演奏データがないための構造検証であり、実録音での検証ではない）。

### 4.3 結果

| 楽譜 | 音符数 | 小節数 | タイの数 | アライメント結果 |
|---|---|---|---|---|
| Bach BWV66.6（コラール） | 163 | 9 | 0 | pairs 163/163、missed 0、extra 0 |
| Bach BWV244.15（コラール） | 194 | 12 | 0 | pairs 194/194、missed 0、extra 0 |
| Chopin Mazurka Op.6-2（ピアノ曲） | 787 | 72 | 4 | pairs 787/787、missed 0、extra 0 |

**結論: `align.py` は MusicXML 由来の参照譜でもコード変更なしで動く。**
ただし変換時に **タイで結ばれた音符の結合**が必須であることがわかった。
MIDI 演奏データでは連続する同ピッチのタイは単に1つの長い音として現れるが、
MusicXML では記譜上「別々の音符＋タイ記号」として符号化されている。
結合しないと、実際には1回しか弾かれていない音が2つの短い音符として
参照譜に現れ、採譜結果との対応付けが崩れる。

### 4.4 未解決・要検討事項

- **アウフタクト（不完全小節）の小節番号ずれ**は今回の3曲では顕在化しなかった
  （すべて完全小節から始まる）。アウフタクトのある楽譜では
  `measureNumber` の扱い（0小節目 or 1小節目）を別途確認する必要がある。
- **繰り返し記号（リピート、ダ・カーポ等）**は本検証では展開していない。
  MusicXML 入稿時は演奏順に音符列を展開する前処理が別途必要（M3 未着手）。
- **運指・強弱記号などの非音符情報**はここでは扱っていない。
  `dynamicLevel` は暫定的に固定値を入れており、実装時は `<dynamics>` 要素からの
  抽出が必要。
- 実演奏との突き合わせができていないため、**タイミングの実測誤差は未評価**。
  ベータで実際にユーザーが自分の楽譜をアップロードするようになった段階で
  改めて検証する必要がある。

## 6. 再現手順

M4/M4.5 の手順でデータセットと参照譜を用意した状態から。

```powershell
# 4. 反復練習
python scripts/perturb_replay.py   # repeat10 を含む全条件を再生成
python scripts/align.py --mode jump --tag jump `
  --conditions r_none r_retry1 r_retry3 r_retry_long r_stop r_partial r_partial_retry r_skip r_repeat10
python scripts/evaluate_replay.py --align-tag jump --tag jump

# 3. 実録音での弾き直し
python scripts/perturb_replay_audio.py --pieces piece00 piece01
python scripts/transcribe_onnx.py --out out/transcribed `
  --conditions a_none a_retry3 a_partial_retry a_repeat10 --pieces piece00 piece01 --threads 4
python scripts/align.py --mode jump --tag jump_audio `
  --conditions a_none a_retry3 a_partial_retry a_repeat10 --pieces piece00 piece01
python scripts/evaluate_replay_audio.py --align-tag jump_audio

# 5. 非ピアノ音の混入
python scripts/add_nonpiano_noise.py --pieces piece00 piece01
python scripts/transcribe_onnx.py --out out/transcribed_nonpiano `
  --conditions clean metronome voice metronome_voice --pieces piece00 piece01 --threads 4
python scripts/evaluate_transcription.py --transcribed out/transcribed_nonpiano `
  --out out/eval_nonpiano.json

# 2. 実 MusicXML（music21 の追加インストールが必要: pip install music21）
python scripts/musicxml_reference.py --source "bach/bwv66.6"
python scripts/musicxml_reference.py --source "chopin/mazurka06-2" --tempo 132
```
